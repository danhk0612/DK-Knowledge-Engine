# T17 — PDF 추출·한국어 검색·AI 답변 품질 개선

T17은 PDF 품질 문제를 **문서 추출 / 검색 / 답변 생성**으로 나누어 개선합니다. 현행 SQLite 지식 DB `schema_version=1`과 HTTP API 형식은 유지합니다. AI가 문서를 학습하거나 지식 DB 생성 시 Qwen GGUF를 사용하는 구조로 바꾸지는 않습니다.

## 1. 제작자 PC: 문서 추출

- 기존 PDF 텍스트 추출은 유지합니다.
- 관리자 **문서 · 지식 DB** 탭의 **PDF 레이아웃 보존 추출**을 선택하면 pypdf의 layout 모드를 사용합니다. 다단·표 형식 PDF에서 읽기 순서가 개선될 수 있지만, 문서마다 차이가 있으므로 결과를 확인하세요.
- **스캔 PDF OCR**을 선택하면 텍스트를 추출하지 못한 PDF 페이지에 대해서만 오프라인 OCR을 시도합니다.
- OCR에 필요한 `pdftoppm`(Poppler), `tesseract`(Tesseract OCR), 그리고 `kor`·`eng` 언어 데이터는 **제작자 컴퓨터에 별도 설치**해야 합니다. 두 프로그램을 실행할 수 있도록 Windows PATH를 설정해야 합니다. 자동 다운로드·설치·클라우드 전송은 하지 않습니다.
- 기본 실행에서는 OCR이 꺼져 있습니다. 해당 도구가 없어도 기존과 동일하게 문서를 색인할 수 있습니다.
- OCR을 켜더라도 텍스트가 있는 페이지의 이미지·표 영역까지 자동 분석하지는 않습니다. 이미지와 글자가 혼합된 페이지는 여전히 누락될 수 있습니다.
- 추출 결과에는 문서별 `extracted_characters`, `chunks`, `warnings`가 기록됩니다. 관리자에서 재생성한 DB 옆에 `knowledge.quality.json`이 생성되고 **품질 보고서 열기** 버튼으로 열 수 있습니다.

개발용 CLI의 예시:

```powershell
python -m builder.knowledge_builder `
  --source "D:\Knowledge\sources" `
  --database "D:\Knowledge\knowledge.db" `
  --default-product-id "manual-test" --rebuild `
  --pdf-layout --ocr-scanned-pages `
  --tesseract "C:\Program Files\Tesseract-OCR\tesseract.exe" `
  --pdftoppm "D:\Tools\poppler\bin\pdftoppm.exe" `
  --ocr-language "kor+eng" `
  --quality-report "D:\Knowledge\knowledge.quality.json"
```

`--pdf-layout`·`--ocr-scanned-pages` 옵션은 기존 DB의 추출 설정이 달라졌을 수 있으므로 `--rebuild`와 함께 사용해야 합니다. 원본 PDF는 수정하지 않고, OCR 이미지 파일은 작업 종료 후 임시 위치에서 지웁니다. 스캔 PDF는 렌더링/OCR 작업 시간과 메모리가 추가로 필요합니다.

## 2. 사용자 PC: 검색 개선

- 기존 FTS5 한국어 접두어 검색과 `product_id`·문서 버전 필터를 그대로 유지합니다.
- 기존 검색이 근거를 하나도 찾지 못할 때만, 완전한 한국어 복합어가 단어 띄어쓰기 차이로 누락되는 경우를 보완합니다. 예: `데이터 베이스` ↔ `데이터베이스`, `사용자로그인` ↔ `사용자 로그인`.
- 짧은 부분 문자열만으로 근거를 인정하지 않으며, 전체 의미를 이해하는 **임베딩·형태소·동의어 검색은 아직 아닙니다.**
- DB 스키마 변경이나 사용자용 검색 모델 추가 없이 적용됩니다.

## 3. 사용자 PC: 모델 답변

- 기존의 **무조건 한 문장** 지시를 없애고, 문제가 복잡하면 최대 5단계로 안내하도록 했습니다.
- 근거는 기본 최대 3개에서 **5개**까지 사용하며, 각 근거에 파일명·페이지·번호를 부여합니다. 입력 근거 텍스트는 합계 최대 4,400자, 근거 하나당 최대 1,100자로 제한해 기본 4,096 컨텍스트의 CPU 추론을 고려합니다.
- 새로 제작하는 기본 CPU 포터블 패키지의 최대 답변 토큰 수는 **192 → 384**로 늘렸습니다. 기존에 배포한 패키지의 `settings.json`은 자동 수정하지 않습니다.
- 충분한 근거가 없으면 답을 추측하지 말라는 지시를 유지합니다. 반환된 `grounded: true`는 **답변의 사실성이 증명되었다는 의미가 아니라**, 검색 근거가 있고 모델이 명시적 답변 거절 문구를 출력하지 않았다는 뜻입니다.
- 모델 선택과 패키징은 [T16](T16_MODEL_PACKAGING.md) 방식을 그대로 사용합니다.

## 4. 세 단계 원인 구별 및 재현

| 판단 단계 | 직접 확인하는 결과 | 결함이 있다면 |
| --- | --- | --- |
| 추출 | `knowledge.quality.json`의 문서별 추출 글자 수, 무텍스트 페이지, OCR 복구 경고 | PDF 처리·OCR |
| 검색 | Client의 **문서 검색**으로 같은 질문을 입력하고 출처·본문 확인 | FTS5·띄어쓰기·청크 분할 |
| 생성 | 검색된 내용이 맞는 상태에서 **AI 답변**과 다른 GGUF의 답변 비교 | 생성 모델·프롬프트·토큰/컨텍스트 설정 |

기존의 `tests/t10_eval.py`는 질문별 기대 근거/답변 조건을 JSON으로 정의해 localhost API에 대해 반복 검사하는 도구입니다. 원본 고객 설명서를 GitHub Actions에 업로드하지 말고, 고객 PC 또는 관리 가능한 내부 개발 환경에서 실행하세요.

```powershell
python tests/t10_eval.py `
  --database "D:\Knowledge\knowledge.db" `
  --cases "D:\Knowledge\quality-cases.json" `
  --port 8765 `
  --output "D:\Knowledge\t17-evaluation.json"
```

테스트 질문은 실제 고객이 자주 하는 질문과 모호한 질문을 함께 작성하고, 최소한 기대 출처와 잘못된 답변이 포함해서는 안 되는 내용을 정의하는 것이 좋습니다. 평가 파일은 문의/답변의 원문을 출력하지 않도록 기존 T10 정책을 유지합니다.

## 5. 고사양 제작기와 소형 사용자 모델의 역할

**가능합니다.** 제작자 PC에서 PDF 렌더링/OCR이나 향후 구조 분석·청크 생성 보조 모델을 더 큰 자원으로 수행하고, 사용자 PC에서는 별도 경량 GGUF로 답변할 수 있습니다. 현재 T17에서는 제작자용 선택적 OCR만 구현했으며, DB 생성용 LLM, 임베딩 생성/질의 인코더 및 AI 기반 문서 재작성 기능은 아직 없습니다.

벡터 임베딩을 제작자 PC에서만 생성하더라도 **사용자 질문에 대한 동일 공간의 임베딩을 만들어 줄 인코더가 사용자 측에도 필요**합니다. 사용자 모델과 동일할 필요는 없지만, 해당 임베딩 파이프라인의 모델·버전 정합성을 지켜야 합니다. 따라서 벡터 검색·모델 교체를 DB 제작만으로 해결됐다고 취급하지 않습니다.

## 자동 검증과 범위

- OCR 실행 호출은 합성 PDF와 모의 OCR로 검증합니다. 실제 한국어 스캔 PDF의 인식률은 자동 CI로 증명되지 않습니다.
- 한국어 복합어 띄어쓰기 검색 성공, 짧은 부분 문자열 오탐 방지, 제품·버전 분리, 문서 근거 5개·길이 상한·거절 동작을 회귀 검증합니다.
- 고객 설명서의 정확한 검색/응답 품질 개선량은 고객별 원문 및 정답 질문 세트로 별도 비교해야 합니다.

## 2026-11-12: 범용 검색·답변 근거 보강 (검증용 브랜치)

- 질문에만 쓰이는 말과 일부 한국어 동사형(예: `확인해야` → `확인`, `재기동해야` → `재기동`)을 제한적으로 정규화합니다. 형태소 분석기나 업무별 용어 사전은 요구하지 않습니다.
- 검색 결과는 같은 단어 개수라도 **문서 본문에 직접 등장한 단어**를 우선합니다. 제목에만 단어가 있는 결과는 답변 근거에서 제외합니다.
- 생성 답변이 제공된 본문·표시된 출처 페이지에 없는 두 자리 이상 숫자/코드/버전을 사용하거나 존재하지 않는 근거 번호를 인용하면, 확인 불가 답변으로 되돌립니다. 목록 번호와 올바른 출처 번호는 제외합니다.
- 합성 매뉴얼을 사용해 회로시험/시뮬레이션, XLS/PDF, 통신장애, 재기동, 사용자 권한, GPU 근거 없음의 6개 검색 사례를 검사합니다. 원본 고객 PDF를 저장소에 넣지 않습니다.
- 추가로 **행 이름·열 이름을 모두 찾을 수 있는 단순한 O/X 권한표**에서는, 답변의 명시적인 가능/불가능 표현이 해당 교차 칸과 반대라면 확인 불가로 처리합니다. 표가 잘리거나 질문이 여러 권한을 섞어 물으면 이 규칙만으로 판정하지 않습니다.
- 숫자 근거 검증에 파일명/경로의 숫자는 사용하지 않습니다. 출처 페이지 번호는 별도로 근거로 인정합니다.
- **한계:** 의미적 참/거짓을 일반적으로 판정할 수 있는 기능은 아닙니다. 표의 권한 의미가 문서마다 다를 수 있고, 표 구조가 손상된 PDF나 여러 주장으로 구성된 답변은 검사 대상에서 빠질 수 있습니다. 실제 PDF와 고객 PC의 GGUF 답변은 별도로 검증해야 합니다. 이 변경만으로 품질 통과나 새 Preview 배포를 선언하지 않습니다.
