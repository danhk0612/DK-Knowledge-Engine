# T18 — 제작용 고성능 LLM 검색 보강

## 목적과 설계

제작 PC에서 고사양 모델로 설명서의 **사용자 질문 형태와 검색 표현을 미리 생성**해 지식 DB에 넣고, 사용자 PC에서는 기존 SQLite FTS5 + 소형 생성 모델만 사용합니다. 제작 모델·제작용 런타임·외부 설치 도구는 사용자 ZIP에 들어가지 않습니다.

기존 `schema_version=1`, 원본문서/청크 구조 및 API 응답을 변경하지 않습니다. 별도 `chunk_search_hints` 테이블과 FTS5 인덱스만 추가하며, 옛 DB도 계속 검색할 수 있습니다.

```text
제작 컴퓨터 (고성능 모델)                 사용자 컴퓨터 (경량)
PDF → pypdf/OCR → 원문 청크 ──────────→ knowledge.db (원문+검색 힌트)
                     │                         │
                     └─ 큰 LLM: 가상 질문 생성  └─ SQLite FTS5 → 원문 청크 → 사용자 GGUF
```

힌트는 **검색 후보를 찾는 용도**이며 LLM 생성 텍스트를 정답이나 근거 문서로 전달하지 않습니다. 모델의 허위 연상·검색 오탐 가능성을 제거하는 것은 아니므로, 배포 전에 실제 질문 평가가 필요합니다.

## 관리자 GUI 사용법

1. **문서 · 지식 DB**에서 원본문서를 등록하고 OCR/레이아웃 옵션을 필요에 따라 선택합니다.
2. **제작용 AI로 문서 검색 표현 보강**을 체크합니다.
3. 제작 전용 모델 실행 방식을 하나 선택합니다.
   - **로컬 AI 서버**: 오프라인 PC에서 이미 실행 중인 OpenAI 호환 Chat Completions 서버의 `http://127.0.0.1:8080/v1/chat/completions` 같은 **loopback** URL을 입력합니다. `모델 ID`는 해당 로컬 서버가 요구하는 모델 이름으로 변경할 수 있습니다. 서버는 모델을 계속 메모리에 올리므로 많은 청크를 처리할 때 유리합니다. 인터넷 URL, HTTP 리다이렉트는 허용하지 않습니다.
   - **로컬 GGUF 실행**: `제작용 GGUF 선택` 및 `실행 파일 선택`으로 모델과 llama.cpp의 CLI 경로를 지정합니다. 실행 파일을 비워 두면 관리자 엔진 템플릿의 `llama-completion.exe`를 사용합니다. `GPU layers`는 별도 GPU용 llama.cpp 실행 파일에서만 효력이 있습니다.
4. **지식 DB 재생성**을 실행합니다. 힌트 생성 실패는 오류로 표시되며 DB의 새 파일로 최종 교체되기 전까지 기존 DB는 보존됩니다. JSON 형식이 틀린 힌트만 건너뜁니다.
5. 사용자 패키지 제작 탭에서 **사용자용 GGUF**를 별도로 선택하고 ZIP을 만듭니다. 제작 모델은 포함하지 않습니다.

제작용 LLM이 충분히 좋은 모델이라도 PDF에서 누락된 표·이미지의 사실을 만들어낼 수는 없습니다. PDF OCR 및 추출 보고서를 먼저 검토하세요.

## 개발용 CLI

```powershell
# 방식 A — 제작 PC 로컬 모델 서버 (권장: 장시간 실행)
python -m builder.knowledge_builder --source "D:\Manuals" `
  --database "D:\Knowledge\knowledge.db" --rebuild `
  --author-endpoint "http://127.0.0.1:8080/v1/chat/completions" `
  --author-endpoint-model "local"

# 방식 B — 별도 로컬 GGUF 파일과 llama.cpp 실행 파일
python -m builder.knowledge_builder --source "D:\Manuals" `
  --database "D:\Knowledge\knowledge.db" --rebuild `
  --author-llama-cli "D:\llama\llama-cli.exe" `
  --author-model "D:\models\author.gguf" `
  --author-prompt-mode jinja --author-gpu-layers 0
```

`--author-max-chunks 20`을 지정하면 새로 생성하는 힌트를 최대 20개 청크로 제한하여 시험할 수 있습니다. 지정하지 않으면 모두 처리하므로 큰 설명서는 오래 걸릴 수 있습니다.

## 검색·보안·호환성

- 기존 FTS5 검색 결과를 우선하며, 비어 있는 결과 공간만 보조 인덱스로 채웁니다. 생성 질문/키워드가 원문에 없는 **사실**을 제공하는 것은 아닙니다.
- 보조 검색도 제품 ID, 문서 버전, 최소 질문 개념 개수 조건을 거칩니다. 사용자가 지정하지 않은 제품 문서는 보이지 않습니다.
- 사용자 ZIP에는 제작 모델이나 로컬 제작 서버 설정이 들어가지 않습니다. 힌트는 지식 DB 안의 텍스트뿐이므로 사용자 런타임의 메모리 부담은 FTS5 인덱스 증가 정도입니다.
- 이 기능은 진정한 벡터 임베딩 검색과 다릅니다. 동의어·문장 표현의 일부만 보완하므로, 의미 기반 검색은 별도 경량 임베딩 모델로 구현해야 합니다.
- 실제 사용처의 문서에 포함된 민감정보가 로컬 LLM의 프롬프트에 들어갑니다. **오직 신뢰할 수 있는 제작 컴퓨터의 localhost 서버**에서 실행해야 합니다. 프롬프트에 포함된 외부 URL은 호출하지 않습니다.

## 평가

동일 PDF와 정답이 정해진 사용자 질문을 대상으로 변경 전후 다음을 비교합니다.

- 문서별 추출 글자/경고 수
- 검색된 원문 청크의 정답 출처 포함률 (Recall@5)
- 고객에게 보여 준 응답의 사실성·누락률과 참조 페이지
- 제작 시간, DB 용량, 사용자 검색 지연, Client 메모리/CPU 사용량

샘플·합성 문서만으로 실제 고객 문서에서 정확해졌다고 주장하지 않습니다.
