# T16 — 사용자 패키지에 포함할 GGUF 모델 선택

## 역할 분리: 지식 DB와 AI 추론

**현재 Knowledge Builder에는 AI 언어 모델을 사용하지 않습니다.** 관리자에서 PDF/DOCX/TXT/MD를 읽어 텍스트를 추출하고, 최대 1,200자 단위로 나누어 SQLite FTS5(기본 `unicode61`)에 기록합니다. 이 과정은 모델 크기와 무관합니다.

반면 Client의 `/chat`은 DB에서 찾은 청크를 **사용자 패키지에 포함된 GGUF**와 llama.cpp에 전달해 문장으로 답합니다. 따라서 제작자 PC에서 고성능 모델을 실행하더라도 현재 DB 제작 방식 자체는 달라지지 않습니다.

미래에 DB 생성용 **OCR, 문서 구조 분석, AI 기반 내용 정리/임베딩**을 도입하면 제작자 PC에서 더 큰 모델을 실행하고 사용자용 Client에는 작은 모델을 배포할 수 있습니다. 단, 이는 기존 Builder와 검색 스키마를 확장해야 하므로 **T16 구현에 포함하지 않습니다.** 임베딩 기반 검색을 도입한다면 쿼리 측에서도 호환되는 임베딩 표현이 필요합니다.

## 관리자에서 모델 선택

1. **사용자 패키지 제작** 탭의 **사용자용 AI 모델(GGUF)** 에서 로컬 `.gguf` 파일을 선택합니다. 비워 두면 기존의 Qwen3 1.7B 기본 모델을 그대로 사용합니다.
2. **프롬프트 형식**을 모델에 맞게 선택합니다.
   - `raw_chatml` — 기존 Qwen3 CPU 패키지에서 확인된 호환 형식입니다.
   - `qwen3` — 기존 Qwen3 Jinja 호출 및 reasoning-off 옵션입니다.
   - `jinja` — 다른 GGUF의 내장 채팅 템플릿을 사용하기 위한 **일반 Jinja** 호출 형식입니다. 모델에 해당 템플릿이 있어야 합니다.
3. **사용자 패키지 생성**을 누르면 선택 파일이 사용자 ZIP의 `models/` 안에 복사되며, 기본 Qwen GGUF를 대신합니다. 모델 절대 경로는 사용자 PC에 사용하지 않습니다.
4. `config/settings.json`의 `model.file` 및 `model.prompt_mode`, `manifest.json`의 모델 경로 및 SHA-256 검증 값이 함께 바뀝니다. 기존 엔진·API·지식 DB 스키마는 유지됩니다.

`models/` 밖의 절대 경로를 클라이언트에 직접 남기지 않으며, 패키지에 포함한 모델을 무결성 검증합니다. **다른 종류의 GGUF라도 무조건 동작한다는 뜻은 아닙니다.** 기본 번들의 `llama-completion.exe`는 T07에서 고정한 llama.cpp v0.8.0 CPU 빌드입니다. 더 새로운 모델 아키텍처는 해당 모델과 호환되는 llama.cpp 실행 파일이 필요할 수 있습니다. 별도 런타임 바이너리와 의존 DLL을 바꾸는 방법은 [T09](T09_MODEL_CONFIGURATION.md)를 참고하세요. 현재 Admin의 선택 기능은 **GGUF 모델 변경**만 자동화하며 llama.cpp 자동 업데이트·모델 다운로드는 하지 않습니다.

사용자 패키지가 만들어진 뒤에도 T09 방식으로 `models/`에 GGUF를 추가하고 `config/settings.json`을 수정할 수 있습니다. 이때 수동 추가 파일은 원래 `manifest.json`의 불변 해시 목록에 자동 등록되지 않습니다.

**라이선스:** 선택한 GGUF의 재배포 권한과 NOTICE·라이선스 고지는 제작자가 확인해야 합니다. 모델 제공처의 LICENSE가 사용자 패키지에 자동으로 수집되지는 않습니다.

## PDF 답변이 불확실할 때 확인할 순서

| 검사 | 증상 | 원인 후보 |
| --- | --- | --- |
| 원본 PDF를 열고 텍스트 선택·복사 | 중요한 문구를 복사할 수 없거나 내용이 깨짐 | 이미지 스캔/PDF 인코딩 문제 — 현재 pypdf는 OCR을 하지 않음 |
| Client에서 **문서 검색**을 먼저 실행 | 정확한 설명이 DB에 있어도 관련 청크가 안 나옴 | PDF 추출·청크 분할·한국어 FTS5 검색 문제 |
| **문서 검색**에서 정확한 구절과 출처가 나오는데 AI 답변이 틀림 | 검색은 성공, 답변만 부정확 | GGUF 모델, 프롬프트 형식, 문맥/토큰 상한 문제 |
| 같은 DB·질문으로 다른 GGUF 비교 | 답변 품질이 모델에 따라 크게 다름 | 모델 추론의 영향 가능성이 큼 |

- **이미지형·스캔 PDF**: 현재 OCR이 없어 텍스트가 추출되지 않는 부분은 DB에 들어가지 않습니다. 고성능 PC에서 동일 Builder를 실행한다고 복구되지는 않습니다.
- **표·다단 구성**: `pypdf` 텍스트 추출 순서가 원본 화면 구성과 다를 수 있습니다.
- **한국어 검색**: SQLite FTS5의 `unicode61`은 한국어 형태소 분석이나 의미 검색 모델이 아닙니다. 단어 변형, 띄어쓰기, 동의어 표현으로 검색 누락이 발생할 수 있습니다.
- **답변 생성**: 작은 GGUF가 좋은 검색 결과를 받아도 누락·혼동·요약 오류가 생길 수 있습니다. Client 설정의 `max_tokens`와 `context_size`, 프롬프트 모드도 영향을 줍니다.

현재 T16에서는 **모델 선택과 패키지 포함**만 변경하며, PDF 추출, FTS5 검색 방식, 청크 크기와 데이터 계약은 변경하지 않습니다.
